# E阶段小结学习总结

## 一、总体知识框架

- **设计对象**：RISC-V NPC（RV32I/M），五级流水线，总线连接内存与外设。
- **仿真层次**：RTL 行为级仿真 → 门级网表仿真 → 后端物理设计。
- **工具链**：Verilator、iverilog、Yosys、GTKWave、ECOS Studio、riscv64-unknown-elf 工具链。
- **核心目标**：功能正确、时序收敛、无 X 态传播、可综合、可物理实现。

---

## 二、RTL 设计与总线

### 知识点
- **五级流水**：IF、ID、EX、MEM、WB；数据前递、冒险处理、valid/ready 握手。
- **总线协议**：Valid-Ready 握手；主设备发 `reqValid`，从设备回 `respValid`；可设计为 1 周期延迟模型。
- **MMIO**：UART 基址 `0x10000000`；`0x10000000` 写数据，`0x10000004` MCR，`0x10000005` LSR；LSR 的 THRE 位为 `0x20`。
- **字节通道**：32 位总线按字节通道返回数据；地址低二位决定数据放在哪个字节；CPU 需正确提取字节。
- **复位策略**：软件可初始化寄存器（如通用寄存器）可不复位；控制信号、状态机、流水线 valid 必须复位；数据通路可被 valid 隔离，X 态可被冲刷。

### 注意事项
- 地址必须完整透传，不能提前对齐后丢弃低二位，否则会读错外设寄存器。
- 总线握手必须严格按 valid/ready 时序，CPU 状态机应等待 `respValid` 再采样数据。
- 写操作注意 `wmask` 字节掩码，支持 `sb`、`sh`、`sw`。
- UART 仿真模型通常简化：LSR 恒返回 `0x20`，表示永远可发送；写 `0x10000000` 直接打印字符。

## 三、仿真工具与流程

### 知识点
- **Verilator**：RTL 二值仿真，速度快，支持 DPI-C，适合日常开发与 DiffTest；不暴露 X 态。
- **iverilog**：RTL 四值仿真（0/1/X/Z），事件驱动，速度较慢，适合排查复位与 X 态传播。
- **门级网表仿真**：仿真对象为综合后网表；需加入标准单元行为模型；信号名乱码，调试困难；主要用于验证综合结果与 X 态。
- **GTKWave**：查看 VCD 波形；红色为 X，蓝色为 Z；用 `Shift+F` 全览，找第一个红色信号并追溯驱动源。

### 注意事项
- `$dumpfile` / `$dumpvars` 必须写在 `initial` 块内，否则报 elaboration 错误。
- `$readmemh` 只认十六进制文本；`.bin` 必须用 `od -An -tx4 -v` 转成 `.hex`。
- iverilog 编译需加 `-g2012` 支持 SystemVerilog 语法；用 `-s tb` 显式指定顶层。
- Verilator 与 iverilog 的 Testbench 驱动方式不同：前者可用 C++/DPI-C，后者用纯 Verilog。

## 四、Testbench 编写要点

### 知识点
- **时钟与复位**：`initial clk=0; always #5 clk=~clk;` 生成 10ns 周期；复位保持若干周期后释放。
- **内存加载**：`$readmemh("program.hex", mem);` 把程序装入 `mem` 数组。
- **总线响应**：`ifu_respValid <= ifu_reqValid;` 用非阻塞赋值模拟 1 拍延迟；LSU 读走 `mem_read`，写走 `mem_write`。
- **function vs task**：`function` 纯组合、有返回值、不能耗时；`task` 可多步、无返回值、可含延时，常用于仿真。
- **系统任务**：`$write("%c", data[7:0])` 打印字符到终端；`$display` 自动换行，`$write` 不换行。
- **时间概念**：`#5` 是延迟 5 个时间单位（由 timescale 决定），不是 5 个时钟节拍；等时钟节拍用 `repeat(N) @(posedge clk)`。

### 注意事项
- `$readmemh` 路径为相对路径，需在包含 `program.hex` 的目录下运行 `vvp`，或写绝对路径。
- 内存数组深度要足够；程序过大时报 “Too many words”，需扩容；程序过小报 “Not enough words”，无害。
- Testbench 中不要实例化不可综合的代码；网表仿真时需删除 `debug_*` 等被优化端口。

## 五、C 程序到机器码

### 知识点
- **流程**：`.c` → `gcc` → `.o` → `ld` → `.elf` → `objcopy -O binary` → `.bin` → `od` → `.hex`。
- **交叉编译**：`riscv64-unknown-elf-gcc -march=rv32i -mabi=ilp32 -nostdlib -ffreestanding`。
- **链接地址**：`-Ttext=0x80000000` 必须与 NPC 的 `RESET_PC` 一致。
- **提取纯二进制**：`objcopy -O binary` 去掉 ELF 头、符号表、调试信息。
- **转 HEX**：`od -An -tx4 -v` 每行一个 32 位十六进制数，小端序，供 `$readmemh` 读取。

### 注意事项
- 程序链接地址与 CPU 复位地址必须一致，否则取指错误、死锁。
- `.bin` 不能直接给 `$readmemh`；必须转 `.hex`。
- 大型测试需确认内存容量与 `MAX_CYCLES`，避免误判 TIMEOUT。

## 六、逻辑综合与网表

### 知识点
- **综合**：RTL → 门级网表；工具 Yosys；脚本 `syn.ys` 包含 `read_verilog -sv`、`chparam`、`hierarchy`、`synth`、`dfflibmap`、`abc`、`write_verilog`。
- **参数固化**：RTL 仿真可通过 Makefile `-G` 或 TB 传参；Yosys 不认 Makefile，需在 `hierarchy` 前用 `chparam -set RESET_PC 32'h80000000 NPC` 覆写。
- **工艺库**：`.lib`（Liberty）描述标准单元面积、延迟；PVT 条件包括 typ/ss/ff、电压、温度；预学习用 `typ_tt` 典型库。
- **标准单元仿真模型**：`.v` 行为级模型，如 `ics55_LLSC_H7CL.v`；网表仿真必须加入，且与综合所用库一致。
- **网表特性**：调试端口因无负载被优化掉；信号名变为乱码；速度极慢；适合验证参数固化、复位、X 态传播。

### 注意事项
- RTL 仿真通过 ≠ 综合正确；关键参数必须在 RTL 仿真、综合、网表仿真中全程一致。
- 网表仿真不要用于逻辑调试；应先在 RTL 层用 Verilator + iverilog 排除所有逻辑与 X 态问题。
- 综合日志 `syn.log` 用于排查；网表文件不应带 `_sim` 后缀时用于后端。

## 七、后端物理设计

### 知识点
- **流程**：Floorplan → Placement → CTS → Routing → Signoff。
- **工具**：ECOS Studio；导入不带 `_sim` 的网表；选择 PDK；设置顶层模块名、时钟名、目标频率、利用率。
- **关键指标**：Die Area、Core Utility、Instance Number、Std Cell Number、Frequency、Setup WNS/TNS、Hold WNS/TNS、DRC Number。
- **时序**：Setup 负值表示超频；可降低目标频率修复；Hold 负值需修保持时间。
- **签核包**：`Export Signoff Package` 导出 `.tar.gz`，含 GDSII、网表、SPEF、SDF、报告等。
- **警告**：缺少 `config.macro_locations` 正常，因为无宏单元。

### 注意事项
- 后端要求网表为面向物理设计的版本，不能含仿真模型。
- 若时序不达标，先降频；若 DRC/LVS 不达标，可降利用率。
- 导出签核包前确保 Flow 全部成功且时序为正、DRC 为 0。

---

## 八、工程组织与 Makefile

### 知识点
- **目录**：`vsrc` RTL 源码、`csrc` C/C++ 代码、`tb` Testbench、`build` 所有产物、`syn.ys` 综合脚本。
- **Makefile 目标**：
  - `make` / `make default`：Verilator 编译生成 `build/NPC`。
  - `make iverilog`：iverilog 四值仿真，生成 `build/iverilog/sim.vvp` 并运行。
  - `make syn`：Yosys 综合 + 编译网表，生成 `build/NPC_Synthesis_sim.v`、`build/sim_netlist`。
  - `make run-netlist`：运行网表仿真。
  - `make run`：运行 Verilator 仿真。
  - `make soc` / `make run-soc`：SoC 仿真。
  - `make clean`：删除 `build/`。
- **构建产物**：`build/NPC`、`build/obj_dir/`、`build/iverilog/`、`build/NPC_Synthesis_sim.v`、`build/sim_netlist`、`build/syn.log`。

### 注意事项
- `$readmemh` 相对路径需与运行目录一致；Makefile 中 `BIN_PATH` 可自动转 hex。
- 工具宏区分：`__ICARUS__` 用于 iverilog RTL 仿真，`SYNTHESIS` 用于网表仿真。
- AI 代写代码时，重点复核复位、参数传递、总线握手、调试端口是否被综合优化。

## 九、核心速查表

| 主题  | 关键点                                    | 注意事项                              |
| :---- | :---------------------------------------- | :------------------------------------ |
| 复位  | 控制路径必须复位；数据路径可被 valid 隔离 | 未复位会导致 X 态传播、死锁           |
| 总线  | Valid-Ready 握手；可 1 周期延迟           | CPU 需等 `respValid` 再采样           |
| 仿真  | Verilator 快、二值；iverilog 四值         | 先 Verilator 排逻辑，再 iverilog 查 X |
| 网表  | 调试端口被优化；信号乱码                  | 只验证顶层握手与参数固化              |
| 参数  | `-G` 给仿真器；`chparam` 给 Yosys         | 全程地址必须一致                      |
| C→BIN | gcc → ld → objcopy → od                   | `-Ttext` 与 `RESET_PC` 一致           |
| 综合  | Yosys + Liberty                           | 工艺库与仿真模型匹配                  |
| 后端  | Floorplan→Route→Signoff                   | 时序负值降频；DRC 非零降利用率        |
