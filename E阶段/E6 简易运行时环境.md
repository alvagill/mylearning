# E6

## 一、工具链与环境配置
- **交叉编译工具链选择**：裸机开发必须使用 `riscv64-unknown-elf-` 工具链，不能使用 `riscv64-linux-gnu-`（后者依赖 Linux 系统调用和 glibc，缺少 32 位 multilib 支持）。
- **multilib 支持**：编译工具链时需显式启用 `--enable-multilib`，否则无法同时生成 RV32/RV64 目标代码。
- **头文件借用**：利用 `picolibc` 提供裸机 C 头文件（如 `stdint.h`），但**绝对不能用 `--specs=picolibc.specs`**，否则会覆盖 AM 自带的链接脚本、启动代码和 `klib`，导致链接崩溃。
- **正确姿势**：仅使用 `-isystem /usr/lib/picolibc/riscv64-unknown-elf/include` 来获取头文件，链接仍由 AM 框架完全掌控。
- **编译加速**：使用 `make -j$(nproc)` 并行编译；安装并配置 `ccache`（修改 `~/.bashrc` 中的 `PATH`）可大幅减少二次编译时间。
- **WSL 注意事项**：代码必须放在 Linux 文件系统（如 `~/ysyx-workbench`），不要放在 `/mnt/c/` 下，否则 I/O 性能极差且 `ccache` 失效；通过 `.wslconfig` 限制内存/CPU 防止宿主机卡死。

## 二、AM 框架与构建系统
- **环境变量**：`AM_HOME` 指向 `abstract-machine` 目录；`BENCH_HOME` 指向 `archbench` 根目录；`NPC_HOME` 指向 NPC 项目目录。可在 `~/.bashrc` 中持久化。
- **ARCH 与工具链**：`make ARCH=minirv-npc` 会加载 `scripts/minirv-npc.mk`，其中需正确覆盖 `CROSS_COMPILE`、`-march`、`AM_SRCS` 等。
- **Makefile 递归**：`make[1]: Entering/Leaving directory` 是递归调用的正常提示，不是错误。
- **include 顺序**：若某个子项目未自动包含平台 mk 文件，可在其 Makefile 中手动 `include $(AM_HOME)/scripts/minirv-npc.mk`。
- **编译产物**：`$(IMAGE).elf`、`$(IMAGE).bin` 分别用于调试和加载；`objcopy` 负责提取纯二进制。
- **修改后清理**：若修改了公共源文件（如 `trm.c`、`timer.c`、Makefile），务必先 `make clean`，避免旧 `.o` 缓存导致“改了没生效”的幽灵 bug。

## 三、RISC-V 指令集与 ALU 微架构
- **ALU 统一双输入设计**：将 `alu_op` 的低 3 位与 RISC-V 的 `funct3` 对齐，最高位区分 `SUB`/`SRA`；立即数通过 `alu_src` MUX 选择后送入 ALU 第二输入，消除专用立即数端口。
- **移位指令**：`SLL/SRL/SRA` 使用 `rs2[4:0]` 作为移位量；`SLLI/SRLI/SRAI` 使用指令中的 5 位立即数（`instr[24:20]`）。`>>>` 是算术右移，要求操作数声明为 `signed`。
- **比较指令**：`SLT` 需将操作数转为有符号（`int32_t`）比较；`SLTU` 直接无符号比较。分支指令中 `bge = !blt`、`bgeu = !bltu`，复用比较器。
- **立即数符号扩展**：I/S/B/J 型立即数必须进行符号扩展，尤其 J 型立即数的位拼接（`{{11{instr[31]}}, instr[31], instr[19:12], instr[20], instr[30:21], 1'b0}`）。
- **跳转指令**：`JALR` 目标地址为 `(rs1+imm) & ~1`；`JAL` 为 `pc+imm`；返回地址均为 `pc+4`。
- **访存对齐与掩码**：地址低 2 位决定字节偏移；`wmask` 表示写哪几个字节；数据写入前需左移对齐（`wdata << (addr[1:0]<<3)`）。`pmem_read/write` 中必须做 `addr - 0x80000000` 映射，且对 UART/时钟等 MMIO 地址提前拦截。

## 四、内存映射 I/O 与外设
- **MMIO 概念**：外设寄存器映射到特定内存地址，CPU 用普通 load/store 访问。
- **UART 行为模型**：地址 `0x10000000` 为数据寄存器，`0x10000004` 为状态寄存器。`pmem_write` 拦截数据寄存器并调用 `fputc`；`pmem_read` 拦截状态寄存器返回就绪状态（建议固定返回 1，保证 DiffTest 确定性）。
- **时钟行为模型**：地址 `0x20000000`（低 32 位）和 `0x20000004`（高 32 位）。`timer.c` 中实现 `__am_timer_uptime()` 读取并拼成 64 位微秒数。
- **AM 抽象接口**：用户程序应使用 `ioe_read(AM_TIMER_UPTIME, ...)` 或 `ioe_read(AM_UART_CONFIG, ...)` 等，而非直接调用 `__am_*` 实现函数。
- **IOE 注册表**：`ioe.c` 中的 `lut` 数组将事件映射到处理函数；缺失的事件会触发 `panic`。添加新外设需同时实现处理函数并注册到 `lut` 中。
- **确定性原则**：所有会影响寄存器值的外设读取，sCPU 和 sEMU 必须返回**完全相同**的值，否则 DiffTest 必报错。推荐使用全局 `g_cycle_count` 作为共享时间源。

## 五、调试与验证
- **DiffTest 机制**：每周期比对 PC 和 32 个通用寄存器。是发现指令实现错误的最强工具。
- **GDB 使用**：`gdb -q ./build/npc`，`run <bin路径>`，崩溃后 `bt` 查看调用栈。若报错“No stack”，说明程序主动 `exit(1)`，检查越界拦截逻辑。
- **反汇编与二进制检查**：`riscv64-unknown-elf-objdump -d xxx.elf` 查看汇编；`xxd xxx.bin | grep` 搜索特定机器码（如 `7300 1000` 即 `ebreak`）。
- **printf 大法**：在 `pmem_read/write` 中打印越界地址，快速定位非法访问。
- **ebreak 退出约定**：程序结束前将状态码写入 `a0`，执行 `ebreak`；仿真环境读取 `a0` 判断 `HIT GOOD TRAP`（0）或 `HIT BAD TRAP`（非 0）。
- **常见坑**：同一文件内不能有两个同名 `halt` 定义；C 代码内联汇编必须放在 `trm.c` 等 RISC-V 编译单元，不能放在 x86 的 `main.cpp` 中。

## 六、性能评估
- **native vs NPC**：`ARCH=native` 在宿主机直接运行，用于功能验证；`ARCH=minirv-npc` 在 Verilator 仿真中运行，用于硬件验证与性能评估。
- **archbench 档位**：`test` 档仅验证功能，不输出 Marks；`train` 档用于性能评分，输出 Marks 和 tok/s。
- **分数含义**：Marks = 参考分数 × (参考机耗时 / NPC 耗时)，反映相对性能。初始单周期无 Cache 的 NPC 分数较低（如 11 Marks），是正常的性能基线。
- **性能测试注意事项**：关闭 DiffTest 和 nvboard；耐心等待长时间仿真；不要被老旧第三方程序的编译错误干扰（如 `file format not recognized` 是工具链配置问题，非 NPC 缺陷）。
- **时间测量**：用 `g_cycle_count` 模拟时钟，既保证 DiffTest 通过，又能让 Benchmark 计算有意义的分数。

## 七、核心注意事项速查
1. **volatile 不可省**：访问 MMIO 和忙等待循环必须加 `volatile`。
2. **地址映射不可省**：`pmem_read/write` 必须做 `addr - 0x80000000`，且先拦截低地址 MMIO。
3. **DiffTest 确定性**：所有外设返回值必须 sCPU 与 sEMU 完全一致，否则关掉 DiffTest 只是权宜之计。
4. **及时 Git 提交**：每个里程碑（编译通过、跑通 hello、跑通 LLaMa、获得性能分数）都 commit，便于回滚。
5. **环境变量持久化**：`AM_HOME`、`BENCH_HOME` 等写入 `~/.bashrc`，避免每次手动 export。
6. **多文件副本风险**：AM 框架下存在多份 `trm.c`/`cte.c`，修改前确认 Makefile 实际编译的是哪一份。
7. **ebreak 与 a0**：程序退出码通过 `a0` 传递，仿真环境据此判断 PASS/FAIL。
8. **工具链 multilib**：裸机 RV32 必须使用支持 multilib 的 `riscv64-unknown-elf-` 工具链，避免 glibc 头文件冲突。

## 八、Trae 对 NPC 架构的重构亮点

本次开发过程中，Trae 对原有 NPC 的 RTL 架构进行了若干关键性重构。这些重构不仅修复了具体 Bug，更重要的是**将 NPC 的设计从“堆砌式”提升到“工程化”层面**，与 RISC-V 规范对齐。以下为重构的核心亮点。

### 8.1 ALU 从“三输入专用”到“双输入统一”

**重构前**：ALU 拥有 `alu_in1`、`alu_in2`、`imm` 三个输入端口，操作码自定义（0=ADD、1=ADDI、2=LUI），每增加一条指令就需要新增一种操作码，且立即数走专用通路。

**重构后**：
- 删除 `imm` 端口，改为**统一的 `alu_in1`、`alu_in2` 双输入**。
- ALU 内部只做运算，操作数的来源（寄存器 or 立即数）由**外部 MUX** 决定：`alu_in2 = alu_src ? imm : rdata2`。
- 操作码 `alu_op` 的**低 3 位与 RISC-V 的 `funct3` 完全对齐**，最高位（`alu_op[3]`）区分 `SUB`/`SRA` 这类同 funct3 但不同语义的指令。

**亮点**：
- **硬件面积更小**：ALU 不再有专用立即数通路，减少 MUX 和连线开销。
- **可扩展性极强**：未来添加 M 扩展（`mul`/`div`/`rem`）时，只需在 `alu_op` 低 3 位沿用 `funct3` 编码，**ALU 接口完全不用改动**。
- **设计哲学与 ISA 对齐**：从“为每条指令定制硬件”转为“为指令族设计通用硬件”，符合工业级 CPU 设计思路。

### 8.2 数据通路的数据选择器（MUX）显式化

**重构后**，NPC 的数据通路中出现了多处清晰的 MUX 设计：
- **ALU 第二输入 MUX**：`alu_in2 = alu_src ? imm : rdata2`（区分 R 型与 I 型）。
- **PC 来源 MUX**：`next_pc = halt ? pc : branch_taken ? pc+imm : jal ? pc+imm : jalr ? (alu_result & ~1) : pc+4`。
- **写回数据 MUX**：`wdata = pc_src ? pc+4 : mem_to_reg ? rdata : alu_result`（区分 JALR / LOAD / 普通 ALU 结果）。

**亮点**：
- **级联三目运算符形成优先级树**：Verilog 综合时自动映射为多级 MUX，直观反映“优先级”语义。
- **每一路选择都有明确语义**：读代码时无需反推逻辑，路径清晰。
- **调试友好**：波形上可以逐级观察 MUX 选择信号，快速定位哪条数据通路出错。

### 8.3 有符号与无符号操作的严格区分

**重构后**，在 `alu.v` 和分支判断逻辑中：
- 显式声明 `wire signed [31:0] signed_in1 = alu_in1;` 和 `signed_in2`。
- `SLT`、`SRA` 使用 `signed_in1`/`signed_in2`，保证 `>>>` 和 `<` 走有符号语义。
- `SLTU`、`SRL` 使用原始 `alu_in1`/`alu_in2`，保证无符号语义。
- 分支判断中分别计算 `br_lt`（有符号）和 `br_ltu`（无符号），通过 `funct3` 选择。

**亮点**：
- **用类型系统表达语义**：Verilog 的 `signed` 关键字替代了手动符号扩展，减少人为错误。
- **同一份数据，两种视角**：同一串位，通过 `signed`/`unsigned` 声明切换语义，与 C 语言的 `(int32_t)`/`(uint32_t)` 强制转换思想一致。
- **避免“隐性符号错误”**：RISC-V 中 `SLT` 和 `SLTU`、`SRA` 和 `SRL` 是最容易混淆的指令，重构后从语法层面强制区分。

### 8.4 Load/Store 的字节级精确处理

**重构后**，Load/Store 实现了精细的字节/半字/字处理：
- 新增 `byte_lsb`、`half_lsb` 计算：`{3'b0, addr[1:0]} << 3`、`{4'b0, addr[1]} << 4`，实现“字节索引 → 位偏移”的换算。
- 使用 Verilog 的 **`+:` 变量位段选择**：`raw[byte_lsb +: 8]`、`raw[half_lsb +: 16]`，动态从 32 位字中选取字节/半字。
- `wmask` 生成支持 SB/SH/SW 三种宽度：
  - `SB`: `4'b0001 << addr[1:0]`
  - `SH`: `4'b0011 << {addr[1], 1'b0}`
  - `SW`: `4'b1111`
- 写入数据左移对齐：`wdata_a = wdata << shift`，保证数据落到正确的字节槽。

**亮点**：
- **用移位代替乘法**：`<< 3` = ×8（字节→位），`<< 4` = ×16（半字→位）。硬件中左移只是“重新接线”，**零成本**，而乘法器非常昂贵。
- **硬件/软件职责分离**：硬件负责“数据左移 + 掩码生成”，C++ 端 `pmem_write` 只负责“按掩码逐字节写”，接口清晰。
- **非对齐访存的核心技巧**：这一套机制是所有 RISC-V CPU 实现 Load/Store 的标准范式，掌握了它，未来实现 Cache、MMU 也能复用。

### 8.5 分支指令的条件判断复用

**重构后**，分支条件判断逻辑采用“并行计算 + 选择”的经典硬件设计：
- 同时计算 `br_eq`、`br_lt`、`br_ltu` 三个基础条件。
- 通过 `case (funct3)` 选择对应的结果，其中 `bge = !blt`、`bgeu = !bltu`，复用比较器。

**亮点**：
- **硬件并行性**：三个比较器同时工作，不依赖 `funct3` 决定“先算哪一个”。
- **减少比较器数量**：只实现 `<` 和 `==` 两种比较器，即可支持全部 6 条分支指令。
- **与 ALU 的 SLT/SLTU 逻辑同源**：分支比较和 ALU 比较使用相同的判定逻辑，代码风格统一。

### 8.6 sEMU 与 sCPU 的同步协调

**重构后**，sEMU（C++ 参考模型）与 sCPU（Verilog 硬件）在以下几个方面严格同步：
- **取指逻辑**：两者都从共享的 `pmem` 数组取指，`pmem[(pc - 0x80000000)]` 的地址映射完全一致。
- **Load/Store 处理**：LB/LH/LW/LBU/LHU 的符号扩展、SB/SH/SW 的字节掩码，两边逐条对应。
- **外设行为模型**：UART（`0x10000000`/`0x10000004`）和时钟（`0x20000000`/`0x20000004`）的读取结果必须一致，否则 DiffTest 报错。
- **ebreak 退出机制**：sCPU 通过 DPI-C 调用 `ebreak_halt(a0)`，sEMU 通过 `halted` 标志，两者通过主循环统一判定退出。

**亮点**：
- **共享内存模型**：`pmem` 数组是 sCPU 和 sEMU 的唯一数据源，避免了“两份数据不同步”的经典陷阱。
- **确定性优先**：外设读取采用固定值（而非随机数），保证 DiffTest 100% 通过；这体现了“验证优先于仿真真实感”的工程取舍。
- **退出机制双轨制**：sCPU 必须通过 DPI-C 通知 C++ 主循环退出，而 sEMU 可直接设置标志；两者通过主循环统一处理，逻辑清晰。

### 8.7 重构的核心哲学总结

| 维度          | 重构前                 | 重构后                 |
| ------------- | ---------------------- | ---------------------- |
| ALU 设计      | 三输入 + 自定义 opcode | 双输入 + funct3 对齐   |
| 立即数处理    | ALU 专用端口           | 外部 MUX + `alu_src`   |
| 有符号/无符号 | 隐式处理               | `signed` 声明强制区分  |
| Load/Store    | 粗略支持               | 字节级精确、wmask 掩码 |
| 分支判断      | 分散判断               | 并行计算 + MUX 选择    |
| 硬件/软件接口 | 混杂                   | 职责分明、数据流清晰   |
| 可扩展性      | 加指令需改多处         | 加指令只需扩展 decoder |
