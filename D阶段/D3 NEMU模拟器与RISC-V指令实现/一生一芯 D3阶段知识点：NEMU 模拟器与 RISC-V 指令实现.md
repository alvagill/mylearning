# 一生一芯 D3阶段知识点：NEMU 模拟器与 RISC-V 指令实现

本阶段的核心是从“硬件连线”转向“软件模拟”，在 NEMU 框架下用 C 语言实现 RV32I 指令集，并通过 `cpu-tests` 和差分测试（Difftest）验证正确性。

---

## 一、环境配置与工具链

| 工具/变量        | 作用说明                                                     |
| ---------------- | ------------------------------------------------------------ |
| `$ISA` / `$ARCH` | NEMU 架构参数，`ISA` 通常为 `riscv32`，组合生成 `ARCH`（如 `riscv32-nemu`）。报错 `Expected $ARCH` 往往是环境变量未加载。 |
| `$AM_HOME`       | Abstract Machine 路径。若拼写错误会导致 Makefile 找不到规则（如 `abstract-machinte`）。 |
| OSS CAD Suite    | 开源硬件工具链全家桶（Yosys、iverilog 等）。终端前缀消失通常是因为 `PS1` 被覆盖，但不影响命令可用性。 |
| GDB 调试         | 类似于硬件的“逻辑分析仪”，用于单步查看 `cpu.pc`、寄存器变化、定位 PC 跑飞或 MMIO 读写异常。 |

**要点**：环境变量配置后必须 `source ~/.bashrc` 使其生效；配置完成后，可通过 `make ARCH=$ISA-nemu ALL=dummy run` 进行首次验证。

## 二、NEMU 核心架构与数据流

NEMU 的文件结构与硬件模块（sCPU）高度映射：
*   **主循环**：`cpu-exec.c` 中的 `exec_once()`，相当于时钟上升沿。
*   **取指**：`inst_fetch()` -> `vaddr_read()`，从内存抓取机器码。
*   **译码**：`inst.c` 中的 `INSTPAT` 宏。
*   **执行**：`INSTPAT` 大括号内的 C 语言运算。
*   **寄存器**：`CPU_state cpu` 中的 `cpu.gpr[32]`。

### 静态 PC（`snpc`）与动态 PC（`dnpc`）
*   **`snpc`**：默认的 `pc + 4`（因为 RV32 定长指令），相当于硬件里连接 PC 和加法器的线。
*   **`dnpc`**：真正要跳转的地址。默认 `dnpc = snpc`。
*   **更新逻辑**：普通指令不修改 `dnpc`；跳转指令（如 `jal`、`beq`）在 `INSTPAT` 内部强制修改 `dnpc`（相当于拉高 MUX 的 select 信号）。

## 三、指令译码的魔法：`INSTPAT` 宏

**核心公式**：`if (((inst >> shift) & mask) == key)` —— 相当于硬件的“与门比较”。

1.  **字符串转数字**：`pattern_decode` 在编译期将形如 `"??????? ????? ????? ??? ????? 00101 11"` 的字符串，遍历转换成 `key`（固定值）、`mask`（掩码）和 `shift`（偏移量）。
2.  **右移 `shift` 的作用**：如果模式串**末尾**有连续的 `?`（不关心位），直接右移将其丢弃，从而缩短 `key` 和 `mask` 的长度，提升 CPU 位运算性能。
3.  **GCC 标签扩展**：利用 `goto *__instpat_end` 配合 `&&`，在匹配成功并执行完逻辑后，直接“飞”出几百行的 `if-else` 链，实现极致加速。

## 四、操作数提取与注册机制（`decode_operand`）

**为什么需要注册？** RISC-V 指令类型不同（R/I/S/B/U/J），其寄存器与立即数的位置完全不同。如果在每条指令里纯手工移位，会写出几百行屎山代码（`Copy-Paste` 灾难）。

**解耦设计**：框架用 `switch(type)` 把格式分离，这就是硬件的“数据选择器”。
```c
switch (type) {
  case TYPE_I: src1R(); immI(); break;
  case TYPE_S: src1R(); src2R(); immS(); break;
  case TYPE_B: src1R(); src2R(); immB(); break; // 必须先注册，否则 panic
  // ...
}
```

### 立即数提取（位操作）

**`BITS(x, hi, lo)`**：本质是 `(x >> lo) & ((1 << (hi - lo + 1)) - 1)`。像剪刀一样，把想要的连续位段“抠出来”。

| 操作           | 作用                                                     |
| -------------- | -------------------------------------------------------- |
| `>> lo`        | 把目标位段的最低位移到第 0 位                             |
| `(1 << n) - 1` | 生成 n 位全 1 的掩码，只保留刚才挪下来的那一段            |
| `&`            | 按位与，裁掉其余无关位                                    |

**拼接与移位**：像 B 型（`immB`）和 J 型（`immJ`）这种被打散成 4 段的立即数，需要分四步处理：

1.  **`BITS` 框选**：把每一段从原始指令中单独抠出来。
2.  **`<<` 移位**：把每段挪到它在完整立即数中的正确位置。
3.  **`|` 粘合**：把 4 段拼回一个整数。
4.  **`SEXT` 符号扩展**：把拼接结果的最高位（符号位）向高位复制，防止负数跳转出错。

```text
immB = BITS(inst, 31, 31) << 12 | BITS(inst, 7, 7)   << 11
     | BITS(inst, 30, 25) << 5  | BITS(inst, 11, 8)  << 1
```

## 五、调试与测试策略

### 遇到 `invalid opcode`

这是正常的“填坑”过程——说明当前指令没有被 `INSTPAT` 匹配到。常用的三种定位手段：

| 手段                          | 说明                                                         |
| ----------------------------- | ------------------------------------------------------------ |
| 看报错里的 Hex 机器码          | 按**小端序**拼装，反推 32 位指令字，再对照手册查 opcode/funct |
| 查看 `nemu-log.txt`（ITRACE）  | 日志里记录了 PC 与执行过的指令流，找到出错前最后一条指令       |
| 反汇编 ELF 文件                | 用 `objdump` 反汇编，确认缺失的是哪条指令（如 `sw`、`jalr`）   |

### HIT GOOD TRAP

程序正常执行到 `ebreak` 并结束的标志。**即便外层 Makefile 显示 FAIL，只要内部 Trap 成功，就代表指令逻辑正确。**

### 测试用例进度

通过 `dummy` 跑通框架后，按需实现 `cpu-tests` 中的核心用例（如 `add`、`sum`），不必强求全过——可以跳过 `string` 等依赖复杂库函数的测试。

### Difftest（差分测试）

将你的 NEMU 寄存器状态与 Spike（标准答案）实时比对，一旦不一致直接报错，能省去约 90% 手动抓虫的时间。
