# 一生一芯 D2 阶段知识点：表达式求值与自动化测试

本阶段核心是手写一个微型编译器的前半段（词法分析 + 表达式求值），再用差分测试验证正确性。

---

## 一、数字转换：`strtol` 而非 `atoi`

| 维度 | `atoi` | `strtol` |
| --- | --- | --- |
| 进制支持 | 仅十进制，`0x80000000` 解析为 0 | 可指定进制（16 或 0 表示自动识别） |
| 错误检测 | 失败与成功都返回 0，无法区分 | 通过 `endptr` 校验是否完整转换 |
| 溢出 | 返回 `int`（32 位有符号），`0xFFFFFFFF` 易触发未定义行为 | 返回 `long`（64 位），处理 32 位无符号寄存器更安全 |

要点：只要涉及进制或边界值，使用 `strtol`，并在调用后检查 `endptr` 是否指向字符串末尾。

---

## 二、Token 类型定义：`TK_` 前缀

`TK_` 是 Token 的前缀，用于定义词法单元类型。自定义枚举**必须从 256 开始**：ASCII 码最大为 255，若与字符码重叠会导致类型判断冲突。

```c
enum {
  TK_NOTYPE = 256,
  TK_EQ,    // 257
  TK_NUM,   // 258（数字）
  TK_HEX,   // 259（十六进制）
};
```

职责划分：`sdb.c` 是命令行入口，只负责接收命令并路由；`expr.c` 负责核心求值运算。指令解析与运算逻辑分离。

## 三、正则匹配失败：`for` 循环缺少 `break`

现象：`+` 号无法被匹配，`[+]` 与 `\+` 均无效，即规则本身没有问题。

根因：`make_token` 的 `for` 循环在匹配成功后未 `break`，循环执行完毕后 `i` 恒等于 `NR_REGEX`，随后被 `if (i == NR_REGEX) return false;` 判定为"未匹配"，直接返回。

修复：
1. 匹配成功后立即 `break`；
2. `if (i == NR_REGEX)` 置于 `for` 循环外、`while` 循环内。

这是典型的 C 控制流陷阱：循环变量的终值不等于"未找到匹配"。

## 四、自动化测试（差分测试 / DiffTest）

### 4.1 除零检测必须实际计算

静态扫描易漏判，如 `10 / (2 - 2)` 的分母并非字面量 0，静态难以识别。

可靠方案：生成器调用 GCC 实际执行表达式；若触发 `SIGFPE` 则丢弃该用例；否则将 GCC 计算出的结果作为标准答案写入 input 文件。NEMU 读取同一 input，用 `eval` 计算后与标准答案比对。该机制即差分测试（DiffTest）。

### 4.2 数字的生成方式

语法树生成法中，数字应**一次性整体生成**（如 `rand() % 99`），而非逐位拼接，否则可能生成 `1 + * 3` 这类非法语法。

### 4.3 测试数据的规模应循序渐进

直接用 32 位随机数会导致溢出与截断：C 语言中 `unsigned result` 在长表达式下会溢出；若 NEMU 内部以 `int` 求值，遇到 `0xFFFFFFFF` 必然出错。

正确顺序：先用小范围数字验证逻辑正确性，再引入极端数据。

## 五、工程化实践

### 5.1 测试代码解耦

将自动化测试逻辑独立为 `sdb-test.c` / `sdb-test.h`，`sdb.c` 仅保留命令路由，避免单文件过长。

### 5.2 简化测试流程

数据流向：GCC 侧生成 input 并计算标准答案，NEMU 侧读取 input 并计算结果，两侧比对。

避免反复切换目录的三种方式：
1. 直接传路径：`(nemu) test ../tools/gen-expr/input`
2. 编写 `run_test.sh`，一条命令完成生成与测试；
3. 在 `cmd_test` 中使用 `system()` 调用生成器。

### 5.3 Log 与性能

Log 是 NEMU 内置的追踪功能，自动记录文件名、行号、函数名，便于调试。

但在自动化测试中，大量打印会造成严重 I/O 瓶颈，拖慢性能。运行测试前应注释掉 `make_token` 中的 Log，或关闭 Trace 开关。

---

## 六、要点汇总

- 类型转换：`strtol` + `endptr` 校验，兼顾进制与溢出。
- 词法设计：`TK_` 枚举从 256 起；匹配成功必须 `break`，未匹配判断放在循环外。
- 分层设计：`sdb.c` 路由命令，`expr.c` 求值，测试逻辑独立文件。
- 测试策略：GCC 作为参考实现，差分比对；数字整体生成；先小规模后极端值。
- 性能：自动化测试期间关闭 Log / Trace。
