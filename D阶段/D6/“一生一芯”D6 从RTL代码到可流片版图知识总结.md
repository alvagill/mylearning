# “一生一芯”硬件设计与仿真核心知识总结

---

## 模块一：Verilog 仿真底层原理与事件模型

### 1. 软硬状态机的等价性
*   **核心思想**：数字电路本质是并行的状态机。计算机是串行的，用 C 语言模拟硬件时，需要把“并行”转换为“串行”。
*   **C语言实现机制**：
    *   用变量（如 `_next` 影子变量）模拟时序逻辑的状态。
    *   用语句执行顺序（先计算组合逻辑 `EVAL`，最后统一更新寄存器 `UPDATE`）模拟状态转移。
    *   Verilator 这类仿真器，正是通过将 Verilog 翻译成高效的 C++ 代码，并利用“平铺（静态调度）+ 影子变量”来实现极速仿真的。

### 2. 层次化事件队列（核心机制）
Verilog 标准规定了仿真器处理事件的 5 个优先级区域，这是解释一切“诡异”仿真现象的根源：
1.  **Active (活跃区)**：阻塞赋值（`=`）、计算、`$display` 在这里立即执行。
2.  **Inactive (非活跃区)**：`#0` 延迟的操作在这里执行。
3.  **NBA (非阻塞赋值更新区)**：非阻塞赋值（`<=`）的**左侧真正更新**发生在这里。
4.  **Monitor (监控区)**：`$monitor` 和 `$strobe` 在这里执行。
5.  **Future (未来区)**：带有非零延迟（如 `#10`）的事件。

### 3. 阻塞赋值 vs 非阻塞赋值
*   **阻塞赋值 (`=`)**：顺序执行，立即更新。用于**组合逻辑**建模。如果在时序逻辑中使用，会导致多个 `always` 块之间出现顺序依赖，引发不可预测的竞争。
*   **非阻塞赋值 (`<=`)**：右侧立即求值，左侧推入 NBA 区统一更新。完美模拟了真实硬件中**触发器在时钟沿同时翻转**的特性。用于**时序逻辑**建模。
*   **致命铁律**：一个变量只能在一个 `always` 块中赋值（单驱动原则），绝不能在同一个块里混用阻塞和非阻塞。

### 4. 数据竞争（Race Condition）与功能不匹配
*   **成因**：多个 `always` 块并发操作同一个变量，且顺序不确定（至少有一个是 Update 操作）。
*   **仿真 vs 综合**：仿真时由于事件队列的随机性，结果可能时而为 0 时而为 1；但在综合器中，它会根据代码优先级或直接判定短路（如 `a=0; a=1;` 会直接综合为高电平 1）。这导致芯片流片后直接变砖。
*   **避坑指南**：
    *   遵守标准的编码规范（时序用 `<=`，组合用 `=`）。
    *   不要在时序逻辑中使用 `#0`。
    *   想看非阻塞赋值后的最终结果，请用 `$strobe` 而不是 `$display`。

## 模块二：逻辑综合（Logic Synthesis）与 Yosys 实战

### 1. 综合的本质
将抽象的 RTL 代码，翻译成由**通用硬件单元**（`$add`、`$mux`、`$dff`）组成的网表（Netlist）。

### 2. 综合三阶段
1.  **粗粒度综合（Coarse-grain）**：将 `always` 块转换为通用单元，并进行面积/性能优化（如加法器复用、状态机提取）。
2.  **细粒度综合（Fine-grain）**：调用 `techmap`，将多位宽的通用单元拆解为单比特的门级单元（如各种门电路）。
3.  **工艺映射（Technology Mapping）**：调用 `abc` 和 `dfflibmap`，将单比特门映射到具体代工厂（PDK）提供的标准单元库中的物理单元。

### 3. Yosys 实战避坑指南（你踩过的坑）
*   **`hierarchy` 报错**：必须先 `read_verilog` 读入文件，才能用 `hierarchy -top 模块名` 指定顶层。
*   **`write_rtlil` 找不到**：旧版本 Yosys 可能废弃该命令，改用 `dump -o xxx.rtlil` 等效替代。
*   **`show` 命令出图失败**：`show` 依赖 Graphviz 和 xdot。若在无图形界面的终端（或 WSL）运行，需使用 `show -format png` 生成图片后，用 `xdg-open` 查看。

## 模块三：PDK 与标准单元库（数字芯片的“建材市场”）

### 1. 标准单元的“四大文件”
*   `.lib`：综合器和 STA 工具用，包含逻辑功能、面积、延迟、功耗信息。
*   `.v`：功能仿真用，纯逻辑模型，无延迟。
*   `.lef`：物理设计（布线/布局）用，包含尺寸、引脚位置、金属层走向。
*   `.cdl`：晶体管级网表（SPICE），用于 LVS 检查。

### 2. 金属层视角的物理结构
*   **芯片是 3D 建筑**：底层是晶体管，上面是金属层（M1~M7）通过通孔（Via）连接。
*   **低层金属**：线细、间距小，电阻大，用于标准单元内部及短距离走线。
*   **高层金属**：线宽、间距大，电阻小，专用于**长距离传输**（如电源网络、全局时钟）。

### 3. 必做题解答：为什么不需要了解所有标准单元？
*   **因为 EDA 工具会自动选型**。人类无法记住几千种标准单元，只需掌握其**命名法则**：
    *   **功能**：`OAI` (或非)、`AOI` (与非)、`DFF`、`LAT`、`BUF`、`INV`。
    *   **驱动能力**：`X1`, `X2`, `X4`（后缀数字越大，驱动力越强，面积越大，但延迟越小）。
    *   **物理属性**：`HVT` (高阈值，慢但省电)、`LVT` (低阈值，快但漏电严重)。

### 4. PVT 角与阈值电压（Vth）
*   **PVT**：工艺(Process)、电压(Voltage)、温度(Temperature)。
    *   芯片设计必须在**最差情况（如 SS 角：慢工艺+低压+高温）**下保证功能正确。
    *   超频的原理：降低温度（液氮）可以提升载流子迁移率，等效于进入 FF（快）角。
*   **Vth 的权衡**：关键路径用 `LVT` 保速度，非关键路径用 `HVT` 降功耗。EDA 工具会自动执行 `Multi-Vt Optimization`。

## 模块四：物理设计（Physical Design）与签核（Sign-off）

### 1. 布图规划（Floorplan）
*   **利用率（Utilization）**：标准单元总面积 / 芯片核心面积。通常取 60%~70%。太高会导致布线拥塞死锁，太低浪费流片资金。
*   **芯片尺寸**：理想是正方形。如果引脚（Pad）数量过多，受限于最小间距，芯片可能会被硬拉成长方形。

### 2. 摆放（Placement）与填充（Filler）
*   **摆放原则**：逻辑相连的靠拢（减小线延迟）；利用 LEF 的 `SYMMETRY` 属性进行镜像翻转（缩短连线）；分散处理缓解拥塞。
*   **Filler 单元**：填满空闲网格。尺寸必须是 `SITE`（最小网格单位）的整数倍。不仅为了化学机械抛光（CMP）平整，也为了保证阱（Well）的连续性和寄生电容计算的准确性。

### 3. 时钟树综合（CTS）
*   时钟需要极高的驱动能力和极低的偏斜（Skew）。
*   需要插入专用的时钟缓冲器（Clock Buffer）。目标：最小化 Latency，平衡全芯片的 Skew。

### 4. 布线（Routing）
*   分两步：**全局布线**（宏观规划主干道）和**详细布线**（微观画线打孔）。

### 5. 签核（Sign-off）—— 流片前的终极体检
*   **STA（静态时序分析）**：基于真实线延迟计算是否满足建立/保持时间。
*   **SI（信号完整性）**：检查信号串扰（Crosstalk），防止信号被干扰产生毛刺。
*   **物理验证（PV）**：
    *   **DRC**：设计规则检查（如线宽、间距），违反就会制造短路。
    *   **LVS**：版图与原理图一致性对比，确保你画的物理连线没有漏接或错接。

## 模块五：硬件工程思维与进阶认知

### 1. PPA 评估（面积、性能、功耗）
*   **Area**：成本核心。
*   **Performance**：由关键路径（Critical Path）的组合逻辑延迟决定。布线后的真实线延迟（Net Delay）比门延迟更致命。
*   **Power**：包括翻转（动态）、内部短路（动态）、漏电（静态）。性能与功耗永远在博弈。

### 2. FPGA vs ASIC
*   **FPGA**：现场可编程，像搭乐高，不用流片，随时试错，但速度慢、功耗高。适合作为复杂系统（如几十亿条指令的 Linux 启动）的硬件加速仿真。
*   **ASIC**：定制芯片，像盖别墅，流片成本极高，但性能极致、功耗最低。
*   **“一生一芯”早期不用 FPGA**：因为早期验证用例小，Verilator 软件仿真编译快、运行快，比 FPGA 漫长的综合布线时间更高效。
