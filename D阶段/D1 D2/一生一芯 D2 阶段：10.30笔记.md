# 一生一芯 D2 阶段：表达式求值（递归下降法）知识点总结

这部分是整个 NEMU 调试器（SDB）中最硬核的部分，相当于用 C 语言手写了一个微型编译器的“语法分析器”和“计算引擎”。

---

## 一、 词法分析（make_token）与正则踩坑

### 1. `regexec` 的匹配逻辑与 `rm_so == 0`
*   **现象**：`regexec` 默认会在字符串中**向后寻找**能匹配的子串，而不是只看开头。
*   **避坑**：必须加上 `&& pmatch.rm_so == 0`。意思是“匹配到的起点偏移量必须为 0”，强制要求正则引擎每次只能从当前指针位置（`e + position`）开始匹配，绝不能跳过前面的字符去后面瞎找。

### 2. 为什么长度 `len = pmatch.rm_eo`？
*   因为 `rm_so == 0` 强制了起点偏移为 0。真正的匹配长度 = 结束位置(rm_eo) - 起始位置(rm_so) = `rm_eo - 0` = `rm_eo`。

### 3. 字符串拷贝与 `\0` 截断
*   数组 `char str[32]` 最多只能装 31 个有效字符 + 1 个 `\0`。
*   **边界判断**：必须写 `if (substr_len >= 32)` 就报错退出。如果刚好是 32，`strncpy` 填满 32 个格子后，再执行 `str[32] = '\0'` 就会造成**缓冲区溢出**（越界写了别人的内存）。
*   **手动加 `\0`**：`strncpy` 不会自动补 `\0`（除非拷贝长度小于源长度），必须手动加上，否则打印时会带出后面的内存垃圾。

## 二、 `p` 和 `q` 的物理意义（递归的灵魂）

*   **定义**：`p` 和 `q` 是当前要处理的 Token 数组（`tokens[]`）的 **闭区间下标**，即只处理 `tokens[p]` 到 `tokens[q]` 这一段。
*   **作用**：
    *   **剥括号时**：`eval(p + 1, q - 1)`，直接收缩边界，丢掉外围的 `(` 和 `)`。
    *   **找主运算符切分时**：如果在下标 `op` 处砍一刀，左边就是 `eval(p, op - 1)`，右边就是 `eval(op + 1, q)`。
    *   **递归终止时**：当 `p == q` 时，说明区间里只剩一个 Token 了，直接返回它的值。

---

## 三、 核心逻辑：`eval` 函数的三大关卡

`eval(p, q)` 永远按照以下顺序判断：

1.  **Dead End（死胡同）**：如果 `p == q`，说明只剩一个数，直接返回该数字，递归结束。
2.  **脱衣服（消除括号）**：如果 `check_parentheses(p, q) == true`，说明整个表达式被一对完整的括号包裹，直接 `return eval(p + 1, q - 1)`。
3.  **砍一刀（找主运算符）**：如果前两个都不满足，说明这是由多个数/括号组合而成的复合表达式。找到**优先级最低**的运算符，将其一分为二，递归求解左右两边的值，然后再做运算。

## 四、 重点解析：`check_parentheses` 的逻辑（你问过的）

### 1. 它是干嘛的？
判断当前区间 `[p, q]` 的首尾是不是**唯一的一对**将整个式子包裹的括号。

### 2. 如果它返回 `false` 会怎样？（不会有问题！）
很多初学者担心返回 `false` 会导致程序崩溃。
*   并不会！因为 `eval` 里写的是 `else if (check_parentheses(p, q) == true)`。
*   如果它返回 `false`，整个 `else if` 不成立，程序会自动向下流入 **`else` 分支**（找主运算符）。
*   **例子**：式子 `1 + 2`。`check` 发现开头不是 `(`，返回 `false`。程序进入 `else`，找到 `+`，完美切分。

### 3. 为什么要有 `if (p >= q) return false;`？
*   在 `eval` 的调用逻辑中，只要进入 `check_parentheses`，`p` 绝对不可能等于 `q`（因为 `p == q` 的情况在上一个 `else if` 被拦截了）。
*   这属于**防御性编程**，防止别人瞎传参数导致数组越界。

## 五、 重点解析：`find_main_op` 找主运算符（你问过的）

### 1. 什么是主运算符？
整个表达式中，**优先级最低**、且**不在括号内部**的运算符。它是最后一步执行的运算。

### 2. 为什么要从右往左扫？（核心考点）
*   因为 C 语言的同级运算符是**左结合**的。
*   例如 `8 - 3 - 2`，等价于 `(8 - 3) - 2`。真正的主运算符是右边那个减号。
*   从右往左扫，你最先碰到的第一个 `+` 或 `-`，就是最后执行的那个运算符。

### 3. 如何避开括号里的运算符？
*   使用 `count` 变量当“保护罩”。
*   从右往左扫时：遇到 `)`，`count++`；遇到 `(`，`count--`。
*   只有当 `count == 0` 时，说明你现在处于最外层，此时碰到的 `+` 或 `-` 才是真正的主运算符。

### 4. 优先级策略
*   扫描时，先记下碰到的 `*` 或 `/`（作为备选）。
*   如果继续往左扫，碰到了 `+` 或 `-`，因为它优先级更低，**直接丢弃备选，锁定加减号为主运算符**，并立即返回其下标。
*   如果扫完了都没碰到 `+` 或 `-`，那就返回刚才记录的乘除号。
