# 一生一芯 D5阶段进阶学习总结：从机器级表示到 AM 抽象层

本阶段核心跨越了从“微观状态机（NEMU）”到“宏观抽象层（AM & Klib）”的认知。重点涵盖了 C 语言底层的调用约定、栈帧、AM 运行时环境的构建逻辑、以及标准库（字符串、格式化输出）的底层手写实现。

---

## 一、 程序的机器级表示（C 与指令的映射）

### 1. 寄存器保存规则与栈帧（Stack Frame）
*   **寄存器分配**：RISC-V 的 32 个寄存器中，`t` 系列（temporary）和 `a` 系列（argument）属于 **Caller-saved（调用者保存）**，用完即丢；`s` 系列（saved）属于 **Callee-saved（被调用者保存）**，必须在退出前恢复原状。
*   **栈帧的诞生**：因为 `ra`（返回地址）寄存器只有一个，当发生嵌套调用（`f` 调 `g`，`g` 调 `h`）时，必须把旧的 `ra` 存入内存（栈），否则会被覆盖无法返回。
*   **函数生命周期**：准备阶段（Prologue）减小 `sp` 分配空间、保存 `ra` 和 `s`；执行阶段（Body）读写局部变量；结束阶段（Epilogue）恢复寄存器、增加 `sp`、执行 `ret`。
*   **常数加载**：大常数必须用 `lui`（高 20 位） + `addi`（低 12 位）两步走。注意 `addi` 的符号扩展，编译器会进行进位补偿。

### 2. 内存布局与变量
*   **四段式结构**（从低到高）：Text（代码） -> Data（全局/静态） -> Heap（向高地址生长） -> Stack（向低地址生长）。
*   **对齐**：为了硬件访存效率，变量地址必须对齐。这也是结构体（Struct）内部会产生 Padding（插空）的原因。
*   **指针与数组**：数组本质是“连续内存 + 地址算术”（`A[i]` 等价于 `*(A + i)`）。对变量取地址（`&x`）会强制将其存放到内存（栈）中，因为寄存器没有内存地址。

## 二、 AM（Abstract Machine）与构建系统

### 1. AM 的本质
*   AM 是一个跨平台的硬件抽象库。它将底层不同硬件（NEMU、真实 sCPU、x86）的差异屏蔽，向上层提供统一的 API。
*   **模块划分**：`AM = TRM + IOE + CTE + VME + MPE`。目前阶段主要涉及 TRM（计算基础、`halt`、`putch`）和 IOE（输入输出）。

### 2. 程序的启动流程
*   程序入口不是 `main`，而是汇编文件 `start.S` 中的 `_start`。
*   `_start` 负责设置栈指针 `sp`（因为 C 语言运行必须要有栈），然后跳转到 `_trm_init`。
*   `_trm_init` 进行 C 环境初始化后调用 `main()`，结束后调用 `halt()`（在 RISC-V 中通常通过内联汇编执行 `ebreak`，触发 NEMU 的 HIT GOOD TRAP）。

### 3. Makefile 的“五层套娃”与参数传递
*   **自顶向下传递环境数据**：顶层的项目 Makefile 引入 AM 顶层 Makefile，后者根据 `$ARCH`（如 `riscv32-nemu`）拆分出 `ISA` 和 `PLATFORM`，依次引入 `riscv.mk` 和 `nemu.mk`，最终把收集好的源文件列表、编译参数传递给最底层的规则。
*   **自底向上执行**：在 `platform/nemu.mk` 中，定义了 `run` 目标，它通过 `make -C` 进入 NEMU 目录，并把 `-b`（批处理模式）等参数作为 `ARGS` 传给 NEMU 可执行文件。
*   **批处理模式（-b）的作用**：让 NEMU 启动后自动执行 `c`（continue），避免每次跑测试都要手动敲键盘，极大地提升了自动化测试效率。

## 三、 Klib：机器无关的运行时库

### 1. 字符串与内存操作（`string.c`）
*   **`strcmp` 的陷阱**：必须将字符强转为 `(unsigned char)` 再比较，否则遇到高位为 1 的字符（如中文）会导致比较结果错误。
*   **`strncpy` 的补零**：如果源字符串比目标长度短，必须用 `\0` 填满剩余空间。
*   **`memcpy` vs `memmove`**：
    *   `memcpy` 不处理内存重叠，从头到尾直接拷。
    *   `memmove` **必须处理重叠**。若目标地址在前（`d < s`），正向拷贝；若目标地址在后（`d > s`），必须**反向拷贝**（从尾部往前），否则源数据会被提前覆盖。

### 2. 格式化输出魔法（`stdio.c`）
整个 `printf` 家族是一个“俄罗斯套娃”，核心在于**解耦**。
*   **分层套娃**：
    *   外层（带 `...`）：`printf` / `sprintf` 负责接收变长参数并打包（`va_start`）。
    *   中层（带 `v`）：`vprintf` / `vsnprintf` 决定把字符输出到屏幕（`putch`）还是内存（`out_buffer`）。
    *   底层引擎：`vformat`。
*   **Sink 与回调**：`vformat` 不关心输出去哪，它只负责解析 `%d`、`%s`，解析出字符后，统一交给 `sink(ctx, ch)` 处理。这就是 C 语言里的函数指针回调（解耦）。
*   **数字排版逻辑**：先取绝对值，用 `% 10` 和 `/ 10` 提取数字并反转。在填充空格或 `0` 时，若遇到负数，**必须先将负号打印出来**，再打印填充符，最后打印数字本体（例如 `-0042`）。
*   **`va_list` 的本质**：它不是容器，而是**游标**（取件单）。底层依赖 ABI 规则，`va_arg(ap, type)` 根据 `type` 的大小从寄存器或栈中取出数据，并向后移动游标。类型必须严格对应，否则指针乱飞。

## 四、 核心认知：计算机是一个抽象层

*   **微观视角**：程序是一个状态机（PC、寄存器、内存状态的变化）。
*   **宏观视角**：计算机是多层抽象叠起来的。从底层的硬件电路（串口寄存器） -> ISA（`sb` 指令） -> AM API（`putch`） -> 运行时环境（`printf`） -> 上层应用。
*   **每一层抽象的目的**：隐藏下层恶心细节，提供上层简单接口。你手写的 `sprintf` 就是抽象层中的一环，最终它依然要落到最底层的机器码上执行。

## 五、 核心要点速查

- 函数调用必存 `ra`，跨调用的变量放 `s` 寄存器（Callee-saved）。
- 指针解引用才产生访存指令（`lw/sw`）。
- Makefile 参数查找：自顶向下 `include`，顺藤摸瓜找 `FLAGS`，最后用 `make -n` 验证。
- `memmove` 反向拷贝的核心逻辑：`if (d > s)` 且重叠时，`while(n--) dest[n] = src[n];`。
- `printf` 底层通过 `Sink` 指针实现了屏幕输出与内存输出的完美解耦。
- `va_list` 是依托 ABI 规范实现的寄存器/栈数据提取游标。
